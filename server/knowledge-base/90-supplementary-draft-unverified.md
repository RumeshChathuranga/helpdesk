### Q: My Moodle enrolment key is not being accepted, what should I check?

Enrolment keys are case-sensitive and are usually distributed by the lecturer through the module's announcement forum or during the first lecture. Check for trailing spaces if you copied the key, and confirm you are enrolling in the correct semester's instance of the module — Moodle often keeps a separate course space per offering. If the key still fails, the module may have self-enrolment disabled; in that case a human agent needs to check with the course coordinator rather than guess at a fix.

### Q: A Moodle quiz or assignment submission failed, can it be reopened?

A technical failure during a timed quiz or assignment upload (session expiry, browser crash, connectivity drop) should be escalated immediately rather than answered automatically, since only the module's teaching staff can decide whether to reopen an attempt or grant an extension, and doing so incorrectly could affect exam integrity. Note the exact time of the failure and the module code when escalating.

### Q: My UoM mailbox says storage is full, what can I do?

Standard UoM mailboxes have a storage quota; once full, incoming mail may be rejected. Clear space by deleting large attachments from Sent Mail and emptying Trash/Junk folders, or archive old mail locally through an email client. If quota still appears full after cleanup, or a higher quota is genuinely needed for role-related reasons, this needs a human agent to check and adjust the account.

### Q: How does a department request a Zoom licence for an event or module?

Departments needing a licensed Zoom account — for example to remove the standard meeting time limit or to support a large webinar — should submit a request through the IT Help Desk specifying the expected number of participants, the date, and how long the licence is needed for. This is a provisioning request and needs a human agent; it is not something that can be granted automatically.

### Q: A lab's MATLAB, SPSS, or AutoCAD licence has expired or the licence server is unreachable, what happens next?

Campus-wide software licences (MATLAB, SPSS, AutoCAD, and similar packages) are managed centrally and renewed periodically. A licence server that is unreachable from a specific lab may indicate a network issue between that lab and the licence server, or that the department's allocation has lapsed. This needs a human agent to check the licence server status and the department's current entitlement — do not tell a requester the licence has simply expired without confirming.

### Q: A lab printer, projector, or lab computer is not working, what should I do?

Physical hardware faults — a printer offline, a projector that won't power on, a workstation that won't boot — always need a technician to visit in person, so these tickets should be escalated with the exact room/building and a description of the symptom. Do not suggest generic troubleshooting steps (power-cycling, cable checks) as a resolution — hand the ticket to a human so a technician is dispatched.

### Q: A DMS or ERP workflow (purchase requisition, leave application, document approval) is stuck, what can be done?

Workflow items stuck at an approval step are usually waiting on a specific approver and are not something the help desk can push through automatically. Escalate with the workflow/document reference number, the step it is stuck at, and how long it has been there, so a human agent can check with the relevant approver or the systems team.

### Q: A student's marks or registration are missing or wrong in LearnOrg/MIS, what should happen?

Any discrepancy in exam results, marks sheets, or registration status in LearnOrg or MIS touches official academic records and must always be escalated to a human agent — this class of request is never auto-resolved, regardless of how routine it looks. Note the module code, the semester, and the student's registration/index number when escalating.

### Q: My account is locked after failed login attempts, when does it unlock?

Repeated failed logins can trigger a temporary account lock as a security measure. If the lock does not clear after a short wait, or the requester needs it lifted urgently, a human agent needs to verify the requester's identity before unlocking the account — this cannot be done automatically, since unlocking on request alone would be an easy way to bypass the account's security.

### Q: How does a department request a new DNS entry or report an IP phone fault?

A new DNS record (for a subdomain, a lab server, or similar) or an IP phone registration fault is a Core Services / Network request and needs to be raised with the systems/network team with the specific hostname, IP address, or extension involved — this is provisioning and diagnostic work that a human engineer has to carry out, not something the automated assistant can complete.

### Q: A departmental or personal web page hosted by the university is not updating or is down, what next?

Content that was updated but is not showing on the live site is often a caching or deployment step that only the web/hosting team can check; a page returning a server error (500) or a security warning (expired SSL certificate) needs the same team to investigate the server directly. Escalate with the exact URL and what changed recently.
